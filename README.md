# SDVX ∇ MOBILE

一个非官方的 Android 竖屏实验项目，复现 SOUND VOLTEX 第七代 NABLA 的界面、演出和部分打歌流程。这个仓库供研究和继续开发，目前的版本还不适合用来正常打歌。

## 当前能用到什么程度

| 项目 | 当前状态 |
| --- | --- |
| 菜单与演出 | 可以浏览部分街机界面、切换领航员、选曲，进入打歌与本地结算。这是目前比较适合体验的部分。 |
| 触屏游玩 | 菜单支持触控。进入打歌后，触屏操作仍有很多问题。 |
| 激光判定 | 判定仍有明显问题，不能据此评估手感或成绩。 |
| Type-C 手台 | 当前输入方案仍需改进，延迟很大，打歌基本不可玩。目前实际用途是控制界面。 |
| 段位考核 | **考核流程未实现。** 工程中有段位资源处理和界面代码，不能完成一场段位考核。 |
| 刷卡与联机 | **真实刷卡流程和联机游玩均未接入。** 本地档案、PIN 和匹配画面只用于本地流程。 |

## 自己构建

仓库包含 C++/Kotlin 运行时、RmlUi 界面源码、Python 转换工具和 Windows 构建脚本。用户在自己电脑上提供有权使用的 `2026101300` 版数据，所有资源转换、签名和 APK 输出都在本地完成。仓库不提供 HDD、游戏素材包或安装包。

**有同版 HDD，还不能保证从空目录一键构建。** 部分转换工具还需要已准备的本地输入，例如角色登记表和判定参数。构建指南列出了能直接运行的命令、缺口和对应路径。先看 [Windows 本地构建指南](docs/BUILD.md)。

如果交给 AI 操作，可以把这段话和本机目录发给它：

> 按 docs/BUILD.md 准备 arm64 手机构建。我的同版数据在［本地路径］，工具链在［独立目录］。通过本地命令读取数据，只向我报告路径、缺项和退出码。先检查构建输入；缺少登记表、工具或资源时列出准确名称，不编造数据。素材、私有表、签名密钥和 APK 都留在本机。等我要求生成 APK 后再封包。
